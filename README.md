# Placement360 — Student & Recruitment Analytics Platform

Placement360 is a student placement analytics project that combines an institutional-style reporting schema, exploratory KPI dashboard, and a machine-learning model for placement outcome analysis.

## Features

- Student-level placement KPIs: placed students, total students, and placement rate.
- Optional institution-data KPIs for student engagement and participating employers when the corresponding fields are present.
- Cohort drill-downs when the uploaded institutional dataset includes fields such as Department and Batch.
- Academic and employability feature analysis: CGPA, internships, projects, certifications, aptitude, soft skills, training and prior academic scores.
- Random Forest classifier to estimate placement outcome from student attributes.
- Evaluation with precision, recall, F1, ROC-AUC and confusion matrix.
- Optional normalized PostgreSQL schema for richer institutional workflows: student records, skills, engagement events, departments, batches, employers, applications, interview rounds, internship records, placement outcomes and offers. It includes cohort placement, recruitment-funnel, employer-participation and engagement views.

## Training dataset

**Campus Recruitment CSV** from Hugging Face:
https://huggingface.co/datasets/Krooz/Campus_Recruitment_CSV

- 10,000 records across the available dataset splits.
- Student performance and employability attributes.
- Target: `PlacementStatus` (Placed / NotPlaced).
- License declared by the dataset card: CC0-1.0.
- Fields include CGPA, Internships, Projects, Workshops/Certifications, AptitudeTestScore, SoftSkillsRating, ExtracurricularActivities, PlacementTraining, SSC_Marks, HSC_Marks and PlacementStatus.

The public dataset does **not** include Department, Batch, company applications, interview rounds or offer counts. The dashboard therefore shows department/batch and recruitment-funnel KPIs only when those columns are supplied in an institution's own CSV. It does not fabricate cohort or funnel data.

## Quick start

Python 3.10+ is recommended.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python data/download_data.py
```

### Run the dashboard

```bash
streamlit run app.py
```

### Train placement outcome model

```bash
python src/train_model.py
```

Generated model and evaluation files are saved under `models/` and `reports/`.

## Optional institution data schema

The SQL file `sql/schema.sql` defines normalized tables for an expanded placement office workflow. The sample public dataset is student-level classification data; it does not populate application/interview/offer tables. Use the SQL schema with institution-authorized data only.

## Automated training and generated reports

The [Train Placement360 model workflow](https://github.com/Anjaney5000/Placement360-Student-Recruitment-Analytics-Platform/actions/workflows/train-model.yml) downloads the 10,000-row dataset, trains the Random Forest model using the publisher's train + validation splits, and evaluates once on the untouched official test split. Generated metrics, predictions, confusion matrix, ROC curve and feature importance reports are committed under `reports/`; the fitted model is attached to the workflow run as a downloadable artifact (30-day retention).

## Modelling notes

- The train/test split is stratified and deterministic (random seed 42).
- Missing numeric values are imputed with the training-set median; categorical variables use the most frequent training value and one-hot encoding.
- The preprocessing pipeline is fitted only on training data to avoid leakage.
- The classifier estimates associations in this dataset; feature importance is not evidence of causality.
- Performance numbers are generated by running the training script. No model scores are invented or hard-coded in this repository.
